# Astro Framework Guidelines

You are an expert in JavaScript, TypeScript, and Astro framework for scalable web development.

## Core Principles

- **Static-first**: Prioritize static generation and minimal JavaScript for optimal performance
- **Component-driven**: Use Astro components as the primary building blocks
- **Type-safe**: Leverage TypeScript for enhanced developer experience and type safety
- **Performance-focused**: Optimize for Core Web Vitals and user experience
- **Accessible**: Ensure semantic HTML and proper ARIA implementation

## Project Structure

Follow project structure from Astro web age [Project Structure](https://docs.astro.build/en/basics/project-structure/)

```
src/
├── components/          # Reusable Astro components
├── layouts/            # Page layouts
├── pages/              # File-based routing
├── content/           # Content collections
├── styles/            # Global styles
├── public/            # Static assets
└── integrations/      # Custom integrations
```

## Component Development

### Astro Component Structure

```astro
---
// Component script (runs at build time)
interface Props {
  title: string;
  description?: string;
  variant?: "primary" | "secondary";
}

const { title, description, variant = "primary" } = Astro.props;
---

<div class={`component component--${variant}`}>
  <h2>{title}</h2>
  {description && <p>{description}</p>}
</div>

<style>
  .component {
    /* Scoped styles */
  }
</style>
```

### Component Guidelines

- **Props Interface**: Always define TypeScript interfaces for component props
- **Naming**: Use PascalCase for component filenames (`Button.astro`, `Card.astro`)
- **Composition**: Favor composition over inheritance
- **Scoped Styles**: Use component-scoped styles when possible
- **Client Directives**: Use sparingly and with specific hydration strategies

### Client-Side Hydration

```astro
<!-- Immediate hydration -->
<Counter client:load />

<!-- Hydrate when idle -->
<SearchBox client:idle />

<!-- Hydrate when visible -->
<LazyComponent client:visible />

<!-- Hydrate on media query -->
<MobileMenu client:media="(max-width: 768px)" />
```

## Routing and Pages

### File-based Routing

```
src/pages/
├── index.astro           # /
├── about.astro           # /about
├── blog/
│   ├── index.astro       # /blog
│   └── [slug].astro      # /blog/[slug]
└── [...catchall].astro   # Catch-all routes
```

### Dynamic Routes

```astro
---
// [slug].astro
export async function getStaticPaths() {
  const posts = await Astro.glob("../content/posts/*.md");

  return posts.map((post) => ({
    params: { slug: post.frontmatter.slug },
    props: { post },
  }));
}

const { post } = Astro.props;
---

<Layout>
  <h1>{post.frontmatter.title}</h1>
  <Content />
</Layout>
```

## Content Management

### Content Collections

```typescript
// src/content/config.ts

const blog = defineCollection({
```

## Styling Guidelines

### CSS Architecture

```astro
---
// Layout.astro
---

<html>
  <head>
    <!-- Global styles -->
    <link rel="stylesheet" href="/styles/global.css" />
  </head>
  <body>
    <slot />
  </body>
</html>

<style>
  /* Component-scoped styles */
  .layout {
    max-width: 1200px;
    margin: 0 auto;
  }
</style>
```

### CSS Best Practices

- **Global Styles**: Import in layouts, not individual components
- **CSS Custom Properties**: Use for theming and responsive design
- **No Preprocessors**: Use native CSS features (custom properties, nesting)
- **Scoped Styles**: Prefer component-scoped styles over global

## Key Conventions

1. **TypeScript First**: Use TypeScript for all components and utilities
2. **Props Interface**: Always define `interface Props` for component props
3. **Component Naming**: PascalCase for component filenames (`^[A-Z][a-zA-Z0-9]*\.astro$`)
4. **Static Generation**: Prefer static generation over SSR when possible
5. **Performance Budget**: Monitor Core Web Vitals and bundle size
6. **Error Handling**: Implement proper error boundaries and fallbacks
7. **Documentation**: Include JSDoc comments for complex functions

## Performance Metrics

- **Core Web Vitals**: LCP < 2.5s, FID < 100ms, CLS < 0.1
- **Bundle Size**: Monitor and optimize JavaScript bundle size
- **Image Optimization**: Use WebP format and proper sizing
- **Caching**: Implement proper caching strategies for static assets

## Anti-patterns to Avoid

### ❌ Don't: Over-hydrate Components

```astro
<!-- ❌ Bad: Unnecessary hydration -->
<StaticContent client:load />

<!-- ✅ Good: No hydration needed -->
<StaticContent />
```

### ❌ Don't: Mix Global and Scoped Styles

```astro
<!-- ❌ Bad: Mixing styles -->
<style>
  .global-class { /* Global scope */ }
</style>

<style>
  .scoped-class { /* Scoped to component */ }
</style>

<!-- ✅ Good: Consistent approach -->
<style>
  .component { /* All scoped */ }
</style>
```

### ❌ Don't: Ignore TypeScript

```astro
<!-- ❌ Bad: No type safety -->
---
const { title } = Astro.props;
---

<!-- ✅ Good: Type-safe props -->
---
interface Props {
  title: string;
}
const { title } = Astro.props;
---
```

## Remember

1. **Static-first**: Prioritize static generation for performance
2. **Type-safe**: Always use TypeScript interfaces for props
3. **Component-driven**: Build with reusable Astro components
4. **Performance-focused**: Monitor Core Web Vitals and bundle size
5. **Accessible**: Use semantic HTML and proper ARIA attributes
6. **Modern features**: Leverage View Transitions and Content Collections
7. **Testing**: Include unit and E2E tests for critical functionality

Refer to [Astro's official documentation](https://docs.astro.build/) for the latest features and best practices.
